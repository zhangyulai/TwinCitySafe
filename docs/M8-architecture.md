# M8 架构与模型边界

## 事故链路

`LeakStart → PipelineLeakService → 原 SimulationEngine/PipelineSimulator → 观测 → LeakDetectionService + LeakLocalizationService → M4 Graph 影响范围 → 隔离比较 → 用户确认 → 共享 ValveService → 后续真实 tick → STABILIZING`。

第二事故类型为 `WATER_SUPPLY_LEAK`，演示名称 `PIPELINE_LEAK_DEMO`，默认 WS-003、severity 0.75 集中配置于 `simulator/leak_config.py`。不允许 Flood 与 Leak 同时存在，暂停的事故也占用场景，必须先 Reset。

复用 M4 的 34 节点、32 管段、10 阀门及 Graph/Isolation 算法。M4 原阀门 API 的数据库校验和状态更新提取到 `ValveService.apply`，M4 API 和 M8 执行都调用它；没有第二份资产/阀门/图数据。

## 仿真与观测

既有正常给水压力约 0.42 MPa、流量约 28 m³/h，保留正弦微小波动。启动后 30 仿真秒正常观测，接着 180 秒将 severity 从 0 平滑增加到指定值。供水连通时使用 `Q = 60 × severity × sqrt(max(P_local, 0))`，单位按软件示范标定。

目标入/出口压力基准分别乘 `1−0.25s` / `1−0.65s`；出口流量乘 `1−0.3s`，入口加估算泄漏量。上游流量增加、下游压力/流量下降均使用 M4 拓扑追踪结果。所有观测复用原有 16 秒时间常数的松弛过程，子步不超过 0.25 仿真秒。隔离后压力与流量目标归零，仍通过该连续过渡演化；上游恢复正常目标。

这是简化的压力/流量传播演示，不求解节点水头和全网水量平衡，不是 EPANET、CFD 或真实水力工程模型。隔离残余泄漏量取入/出口观测流量差随松弛衰减，不把受压供水公式当作封闭残水的严格物理定律。

## 检测与定位

检测输入仅为观测、启动前基准、前一观测和时间差。归一化因素及权重：压力偏离 .30、流量偏离 .25、压力下降速率 .10、流量增长速率 .10、入出口流量不平衡 .25。集中阈值 .35/.55/.75 分别进入 SUSPECTED/CONFIRMED/HIGH；稳定后的趋势项可能减小，分数不必单调，记录峰值及确认时刻。

定位函数只接收观测列表、基准和 M4 Graph，不接收目标 ID 或 severity。每根连通给水管的分数由流量不平衡 .35、局部压力差 .25、压力残差 .20、流量残差 .10、邻接一致性 .05、下游传播 .05 计算，降序 Top 3。API 中注入 ID 是演示真值，仅仿真器使用；UI 镜头和粒子使用已确认的排名第一管段。未达疑似阈值不发布排名，启动镜头只聚焦给水区域。

百分比是软件匹配分数，未经概率校准。隔离时排除无供水管段继续定位会误导，因此保留最后确认位置作为历史证据，并将当前异常强度明确改为残余流量匹配；人工重新开阀后恢复基于当前观测检测，不继续声称受控。

## 风险与服务影响

风险由观测估算泄漏流量、压力损失、M4 影响建筑、服务损失和增长项构成，权重分别 .50/.20/.10/.15/.05，分项归一化，范围 0–100。压力/建筑/增长项乘当前泄漏强度，隔离后随观测自然下降，服务损失项保留。WS-003 隔离影响 2/5 建筑，完全衰减后仍约 6 分（0.4 × 15），不是全部恢复为零。

确认后调用 M4 `get_affected_buildings` 和 `get_downstream`。实际停水建筑由初始连通节点减去当前连通节点计算，服务中断与泄漏状态分开。风险规则不是 M6 XGBoost；Leak 活跃时 Risk 页停用 Flood 预测轮询，显示规则分解及拓扑影响。

## 比较与执行

候选直接来自 M4 `find_isolation_options`。WS-003 的三种阀门边界分别为 V-W-03 / V-W-02 / V-W-01，影响 2/4/5 栋、隔离长度约 86.92/185.51/224.39 m。只比较阀门数量、建筑、长度、服务损失，没有自动胜出者，也没有冒充水力反事实曲线。

比较保存图/阀门 SHA256、疑似管段、全部给水压力流量快照、事故及仿真时刻。以下任一变化拒绝执行：事故或首位变化、图/阀门哈希变化、已执行、超过 60 仿真秒、任一观测压力差 >0.03 MPa 或流量差 >5 m³/h。前端提示不是最终校验，后端执行前重新计算候选并检查共享阀门服务。

确认文字固定为“仅作用于软件仿真，不控制真实阀门。”。共享控制锁内短事务提交阀门与执行记录后才更新内存图，失败不施加实时动作；执行不写压力、流量或风险。暂停时阀门指令提交，但压力/流量冻结，继续后自然衰减。泄漏量 <0.25 m³/h 标为 CONTAINED/STABILIZING，告警仍 active，事件不关闭。

## 存储与实时

迁移 `f6f65d1e093a` 继承 `adab6941d89a`，新增 events、snapshots、isolations 三表。告警与事件流随事件 JSON 持久化，告警 ID 按场景固定，不因等级变化新建。快照每 5 墙钟秒写入，与 1 Hz WebSocket 独立。采样锁防止后台与 API 并发覆盖；断库按场景只保留最新状态重试，未写满全量历史不能补造。比较缓存最多 30 条、事件展示最多 200 条、待写场景达到 50 拒绝新增启动。

`PIPELINE_LEAK_EVENT` 与完整实时快照共用原连接，队列保留事件、合并实时快照。断线重连从完整状态恢复。前端趋势最多 1800 点及 60 仿真分钟，暂停不重复追加，场景/会话/Reset 清空，断线保留。

Reset 恢复本次 M8 关闭过的阀门至启动前状态，不覆盖其他人工阀门修改，保留数据库历史。重启标记旧事件 interrupted，不自动续演；已持久化关闭阀门仍属于 M4 资产状态，需要人工恢复。单 worker 内存引擎，不具备分布式事务恢复能力。

## 三维

增量扩展 PipelineManager、BuildingManager 和原 DigitalTwinScene。120 个预建 Points 和一个脉冲环；每帧只改位置缓冲与透明度，不创建新 geometry/texture。等级红橙黄、隔离灰、受影响建筑琥珀色；预览复用 Outline 和 M4 trace。关闭对象释放 geometry/material、监听器和图表。受控后保留原位置证据，特效强度按残余流量衰减。
