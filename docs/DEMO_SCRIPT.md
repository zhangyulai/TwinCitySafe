# 比赛演示操作脚本

准备：运行 `./prepare-demo.sh`、`./start-demo.sh`，打开 `/dashboard?demo=1`，检查系统就绪与浏览器实时连接；使用正常监测状态，预先保留已关闭的 Flood / Leak 档案。默认均衡质量，需实机测 FPS。演示重置保留历史，不能代替业务关闭。

## 五分钟：一个现场事故 + 一个历史闭环

10× 下暴雨达到第 29 仿真分钟本身就需约 174 墙钟秒。两个完整现场闭环再加讲解通常超过五分钟，因此此版明确使用历史档案展示暴雨，将泄漏作为现场主线；不跳过引擎、不伪造演化。

| 时间 | 操作 / 页面 | 观察 | 一句话说明 |
|---|---|---|---|
| 0:00–0:35 | 综合态势，打开系统状态后收起 | 实时连接、3 台设备、32 条管段、园区空间 | 一个时钟连接地上地下与设备环境。 |
| 0:35–1:15 | 一键管网泄漏，默认10× | 压力下降、流量残差、疑似 Top3 | 定位来自当前压力流量与拓扑关系。 |
| 1:15–1:45 | 异常确认后暂停，比较隔离候选，选择 V-W-03 并确认；继续 | 两栋建筑受到供水影响 | 人工选择，控制只作用于软件仿真。 |
| 1:45–2:25 | 等待 STABILIZING，暂停；事件复盘接单→处理→完成→关闭 | 泄漏受控但供水中断仍保留 | 事件关闭不等于自动恢复阀门和供水。 |
| 2:25–3:15 | 当前泄漏档案关键节点、回放、模板报告 | 历史阀门、风险、工单和关闭记录 | 历史回放读取保存的数据，不改实时状态。 |
| 3:15–4:30 | 打开预存已关闭暴雨档案，跳至峰值、处置、稳定，查看误差 | 水位峰值、雨势回落、双泵、实际误差 | 物理与 ML 预测可对照，人工干预后的误差如实保留。 |
| 4:30–5:00 | 返回综合态势，确认重置 | 恢复正常监测，档案仍在 | 从监测到复盘，形成可追溯的安全闭环。 |

根据讲解操作速度预留弹性。若班组流转耗时较长，优先展示真实档案，不声称现场已经关闭。

## 八分钟：两类现场闭环

下表是操作预算，不是系统保证。可先排练一次；以运行状态为准，绝不为了赶时间直接写入水位或风险。

| 时间 | 操作 / 页面 | 观察 | 一句话说明 |
|---|---|---|---|
| 0:00–0:20 | 首页系统状态，一键暴雨 | 10×实时引擎启动 | 这是既有雨势回落场景，各方案共用相同雨量计划。 |
| 0:20–1:15 | 智慧运维 P03，回到应急推演 | 第3仿真分钟轴承退化，效率与温振变化 | 故障改变有效排水能力。 |
| 1:15–2:40 | 风险研判，解释当前/未来与物理/ML两条线 | 10/20/30分钟预测与贡献 | XGBoost 学习软件仿真分布，不是因果决策器。 |
| 2:40–3:30 | 回应急推演，达到高风险后暂停并比较；选择B确认后继续 | 同基线四分支、资源与水位比较 | 方案由人主动选择，预测不偷偷修改真实状态。 |
| 3:30–4:50 | 等到稳定且风险<60，工单完整流转并关闭 | 泵能力增加、雨势回落，积水仍可能保留 | 风险下降由雨势与泵排水共同产生。 |
| 4:50–5:20 | 回放暴雨峰值与处置，显示实际预测误差；重置 | 历史报告与真实后续观测 | 报告保留该事件的实际误差。 |
| 5:20–6:05 | 一键泄漏，观察排名确认后暂停 | WS-003 排名与压力流量 | 泄漏定位使用规则与图搜索，不套用内涝模型。 |
| 6:05–6:45 | 比较隔离、预览V-W-03、确认并继续 | 泄漏衰减、科研楼B与实验楼C停水 | 处置效果与服务损失同时呈现。 |
| 6:45–7:35 | 稳定后完成工单、关闭，回放关键节点 | 历史阀门与供水末态 | 可追溯每一次人工操作。 |
| 7:35–8:00 | 回首页、演示重置 | 两类 CLOSED 档案保留 | 平台覆盖两个真实软件事故闭环。 |

提示：比较存在有效期，10× 会放大操作时间影响，建议先暂停再比较。演示流程先完成工单，再在场景稳定时人工关闭；当前 Close API 硬校验稳定状态与人工确认，不强制工单完成。持续暴雨默认原场景可能无法回落，因此比赛入口复用 M7 明示的 30–35 分钟雨势回落计划。
