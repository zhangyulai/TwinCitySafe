# M10 数据来源审计

审计对象为比赛展示页面与其现有 API / Store / Simulator。软件仿真产生的实时数值、数据库真实保存的仿真记录、模型推理结果分别标识；“真实网络 / 数据库验证”不表示真实园区传感器数据。M10 未训练新模型，未调整 M3 / M6 原始模型指标。

## 综合态势 `/dashboard`

| 指标 / 内容 | 实际来源 | 类型 | 可解释性与边界 |
|---|---|---|---|
| 园区运行状态 | `realtime.devices`、`pipelines`、设备活动告警与活动 Flood / Leak 引用 | 实时状态聚合 | 无事故且无异常/离线/隔离时“运行平稳”；存在资产异常显示“需要关注”；活动场景显示“事故演化中”。这是离散运行态，不是综合安全分。连接中断另行标识并保留最后状态。 |
| 在线设备 / 总设备 | 当前 WebSocket `devices` 数组；非 `offline` 计在线，包含待机设备 | 实时仿真 | 不再使用旧 `system.onlineDevices` 汇总字段；展示的是实际接入仿真引擎的设备，不借用静态建筑设备数。 |
| 异常 / 离线设备 | `status=warning/offline`、非正常 fault 或 `analysis.isAnomaly`，按设备去重 | 规则 / 模型状态聚合 | 显示关注对象数量，不把设备异常概率相加。 |
| 管段数量 / 需关注 | `realtime.pipelines.length`；`status != normal` 包括 warning/offline/isolated | 实时仿真资产状态 | 已隔离管段属于需关注对象，不能继续以固定绿色状态灯表示正常。 |
| 当前告警 | 设备 `analysis.activeAlarmId`、当前 Flood `alarm`、活动 Leak `alarm`，按 ID 去重 | 规则 / 异常模型事件 | 当前状态中的活动告警；不是全库告警总量，也不将重连次数算作告警。 |
| P03 温度、振动、电流、效率、健康 | 同一实时状态中的 P03，设备仿真器与 OperationService | 实时仿真 / 规则健康 | 保留单位与原始精度；未连接时显示 —，不补正常值。 |
| 气象 / B2 水位 | `state.weather`、`environment.b2WaterLevel` | 实时软件仿真 | 日常基础水位和活动内涝水位明确区分；雨量是场景统一真值。 |
| 水位趋势 | `useRealtimeStore.history` 最近 60 个已收到模拟采样 | 前端实时缓存 | 纵轴随实际观测扩展，避免原 3 cm 固定上限截断事故值；不新增点、不重写采样、不当作未来预测。 |
| 当前风险 | 当前 Flood / Leak 的 `riskScore` 与等级 | 参数化规则模型 | 无事故不显示虚构风险分；不同场景分别解释，未合成为全园区“科学指数”。 |
| 未来 30 分钟风险 | `riskApi.prediction().mlForecast` 的 +30 min 项 | XGBoost 模型推理 | 仅活动内涝展示；模型不可用显示 — 和降级说明；泄漏明确标识该模型不适用。 |
| 最近事件 / 档案数量 | `GET /incidents?limit=3` 的 `items` / `total` | 数据库 | 不在 GET 时回填或新建事故；失败仅提示档案不可用，不影响实时卡片。 |

源码入口：`frontend/src/views/Dashboard/index.vue`、`store/useRealtimeStore.ts`、`api/review.ts`。

## 智慧运维 `/operation`

| 指标 / 内容 | 实际来源 | 类型 | 可解释性与边界 |
|---|---|---|---|
| 设备列表、额定参数、安装与维护日期 | Device 数据库资产，经 `/devices` API | 软件示范资产 | 实际已入库设备，不等同真实园区设备；默认 P03。 |
| 温度、振动、电流、转速、效率、运行时长 | 统一实时状态的 DeviceState | 软件仿真 | 连续动态值由模拟器演化；离线/待机工况与正常运行分开。 |
| 健康指数与等级 | `HealthService` 的归一化偏离、规则权重和时间平滑 | 规则模型 | 权重与阈值在 `health_config.py`；非厂家认证阈值。缺少 analysis 显示等待数据，不以 0 健康度替代。 |
| 异常分数与等级 | `AnomalyService` 已保存 Isolation Forest 的实际推理 | 机器学习模型 | 分数是偏离程度，不是故障概率；缺模型保留 unavailable；启动与非运行工况有独立状态。 |
| 偏离度贡献 | 观测相对配置基线的偏离 | 规则解释 | 页面仍明确“偏离度贡献 / 非 SHAP”，不包装为 Isolation Forest 因果解释。 |
| 维护建议 / 活动告警 | MaintenanceService / AlarmService | 规则建议 / 数据库事件 | 建议用于软件演示；不自动施加设备动作；持续异常按已有 ID 更新。 |
| 5 分钟趋势 | `deviceHistory` WebSocket 缓存，最多 300 点 | 实时观测缓存 | 断线保留上次值；暂停不制造新观测；按实际采样时间展示。 |
| 1 / 6 / 24 小时趋势 | DeviceTelemetry 数据库采样 API | 数据库历史 | 固定墙钟采样，最多 600 个降采样点；无历史明确提示，不填造曲线。 |

## 地下管网 `/pipeline`

| 指标 / 内容 | 实际来源 | 类型 | 可解释性与边界 |
|---|---|---|---|
| 长度、管段、节点、阀门、材料、端点 | Pipeline 数据库资产 / PipelineNetwork | 软件示范资产 | 总长为实际边长度之和；没有接入真实 GIS / BIM。 |
| 正常率 | 当前管段状态与资产集合；尚无实时状态时使用资产登记状态 | 状态统计 | 不是管网可靠性模型；页面同时标注资产/拓扑/实时来源。 |
| 压力、管段流量、运行状态 | `state.pipelines` | 软件仿真 | 简化管网状态模型，不是 EPANET 或逐段精确水力解。 |
| 上下游、影响建筑、隔离范围 | Graph Search / PipelineGraphService | 拓扑计算 | 由节点和边连接关系推导，不是模型猜测；设计方向与实时流动概念分开。 |
| 疑似定位 Top 3 | LeakLocalizationService 读取观测压力/流量/不平衡与邻接一致性 | 规则与拓扑匹配 | 定位器不读取注入目标真值；百分比是匹配度，不是已校准概率。 |
| 检测分数、压力变化、流量变化 | LeakDetectionService 的观测偏离与窗口变化 | 规则检测 | 参数化阈值用于软件演示，无真实传感器校准保证。 |
| 估算泄漏量、泄漏阶段、风险 | Leak 仿真状态及既有规则风险分解 | 简化物理 / 规则 | 估算泄漏量与管段观测流量不同；泄漏未使用内涝 XGBoost。 |
| 隔离候选、阀门数、长度、影响建筑 | 真实当前图上的隔离算法与已保存比较 | 拓扑反事实比较 | 服务损失指数非金额；方案由用户选择，执行前确认并校验过期。 |
| 泄漏受控 / 供水中断 | 当前 Leak 执行与管网状态 | 仿真结果 | 受控不等于服务恢复；已停水建筑继续显示。 |

## 风险研判 `/risk`

| 指标 / 内容 | 实际来源 | 类型 | 可解释性与边界 |
|---|---|---|---|
| 当前风险、积水与规则贡献 | 当前 FloodState | 规则 / 物理 | 当前评分与未来 ML 解释分开展示。 |
| +10 / +20 / +30 物理预测 | FloodForecastService 对独立状态副本前推 | 简化物理模型 | 假设降雨计划与设备趋势继续；保留执行过渡与待执行状态，无真实引擎副作用。 |
| +10 / +20 / +30 机器学习预测 | 六个保存的 XGBoost JSON 模型 | 仿真训练模型 | 水位 / 风险各三个时距；训练分布来自仿真，不能声称真实城市泛化。 |
| 模型一致度 / 差值 | 同一基准的物理与 ML 输出差 | 模型间比较 | 不是概率或统计置信区间；不作为因果方案优劣判定。 |
| 主要因素 | 原生 TreeSHAP，或明确标注的 importance/deviation fallback | 模型解释 | 原生贡献可加和；近似排序不可加和；均不是因果解释。细节可展开。 |
| 已到期误差 | PredictionEvaluationService 对后续真实仿真观测进行对齐 | 数据库 / 真实后续状态 | 未到期不造 actual；人工干预会影响误差。 |
| 模型版本、样本数、划分、测试指标 | `/risk/model/status` 的模型 metadata 与真实 metrics | 已保存训练报告 | 页面摘要保留 XGBoost 身份和实际样本数，明细折叠；M10 未重训、未改变原指标。 |
| 泄漏事故时的风险页 | LeakSummary 的当前 LeakState | 实时 / 规则 | 明确内涝 ML 不适用于泄漏，不显示无关预测图。 |

| 指标 / 内容 | 实际来源 | 类型 | 可解释性与边界 |
|---|---|---|---|

| 泵效率、健康、有效能力 | Device 资产额定值、设备退化与启动过渡 | 资产 / 实时 / 规则 | 有效能力由活动泵额定值 × 效率计算，不再次重复扣减 HI。 |

| 选择、执行、动作和事件流 | 人工操作、EmergencyExecution、统一 WebSocket | 数据库 / 实时事件 | 执行先保存意图、随后按仿真时间施加；软件确认不控制真实设备。 |

## 全局显示与保留的静态示例

- Header 时间为浏览器本地时间；后端状态来自 health/readiness；实时状态来自实际 WebSocket 客户端连接。服务端 WebSocket readiness 与浏览器连接两项区分。
- System Readiness 检查后端、数据库、推送服务、已加载模型、管网图；Three.js 实际上下文由浏览器自检。自检只读，不启动或重置事故。
- 画质、帧率、draw calls、geometry/material/texture 是当前浏览器渲染诊断，不是业务指标。软件渲染不能作为比赛 GPU 性能承诺。
- `three/building/metadata.ts` 仍有静态建筑示例属性：面积、楼层、设备数、告警数、安全指数和基础风险色。建筑详情/基础风险模式保留“示例”身份；这些值不进入 Dashboard 实时在线数、异常数、当前告警或运行态判断。默认地上模式不以静态风险冒充当前事故。
- 程序化建筑、道路、树木、灯光、雨粒子、网格、动画均是显示资产；事故效果由真实状态驱动，视觉插值不能解释为新增观测。
- M10 移除了 Dashboard 的旧里程碑占位、固定管网正常灯和不适用的系统设备总量。所有真正未知的关键数值显示 `—` 或“未记录”，不改成更好看的值。
