# 可用于比赛材料的事实

以下是项目真实实现及已保存模型报告的数据。软件仿真事实不能描述为真实城市部署结果；最终浏览器数量与耗时见 M10 验收记录。

| 内容 | 可引用事实 | 证据 |
|---|---|---|
| 产品 | 六大页面，两个软件事故闭环：暴雨内涝、管网泄漏 | 六路由；`test:final-demo` |
| 实时通信 | 单应用 WebSocket，1 Hz 推送，支持暂停、1/2/5/10×比赛时钟 | realtime service / demo API |
| 设备资产 | 3 台排水泵 P01/P02/P03，每台额定120 m³/h | readiness 与数据库资产 |
| 管网资产 | 34 节点、32 管段、10 阀门 | readiness / pipeline graph validate |
| 应急模板 | FLOOD-A / FLOOD-B / FLOOD-C 三模板，另有不可执行BASELINE | 方案数据库与比较API |
| 设备模型 | Isolation Forest，训练10000条软件样本，独立评估3564样本 | `algorithm/anomaly_detection/reports/metrics.json` |
| 设备原评估 | precision0.9676、recall1.0000、F1 0.9836，正常误报率0.0328 | 原M3保留报告，不是现场准确率 |

| 历史回放 | Flood/Leak档案、连续插值与离散边界、工单、关闭和模板报告 | M9与M10真实数据库验收 |

算法身份：Isolation Forest用于设备异常，XGBoost用于内涝预测，图搜索用于拓扑追踪/隔离，规则用于当前场景风险，物理分支用于反事实比较。项目没有 LLM Agent、自动应急决策、真实传感器接入或逐段高精度水力求解。

原训练测试只反映仿真分布。人工干预及新工况下的实际误差必须引用对应事件档案，不把高R²写成真实园区预测精度。软件渲染FPS不可代替比赛GPU性能。

本轮最终浏览器验收共19个脚本：15个历史回归（包含4个状态fixture）+4个比赛版验收；全部通过。Final Demo 实际完成两类现场闭环，详见M10验收。
