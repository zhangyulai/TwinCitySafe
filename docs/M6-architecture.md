# M6 Risk Prediction Engine

## 范围

保留 M5 物理 rollout，新增由软件仿真数据训练的六个 XGBoost 回归器。模型仅学习当前仿真分布，不能代表真实城市泛化能力，不用于真实安全决策。M7 应急动作、M8 泄漏、M9 复盘均未实现。

```text
独立 M5 场景副本 → 统一 build_features → 场景分组 → 训练 / 评估 → 原生 JSON 模型
实时引擎副本 → 同一 build_features → 六模型推理 ─┐
            → 原 M5 物理 rollout ─────────────┼→ 预测差异 / 模型一致度 → Risk / Dashboard
            → +30min TreeSHAP ────────────────┘
真实后续引擎观测 → 对齐预测时刻 → actual - predicted → 误差采样
```

## 数据与标签

`algorithm/risk_prediction/` 包含 config、simulation、features、dataset、generate_dataset、train、evaluate、inference。生成器创建独立引擎并复制，直接调用已有 WeatherSimulator、DeviceSimulator、FloodSimulator 和 FloodRiskService；不连接运行中的 Web Demo，也不改写其状态。

250 个独立场景，每场景240条观测、每10个仿真秒一条，共60000样本。每条输入对应 +600/+1200/+1800 秒的真实模拟状态。积分步长5秒，与 M5 forecast 一致；与在线0.25秒子步间的小差异通过 rollout 对照测试检查。

相邻样本的未来区间大量重叠，生成器复用同一场景副本前推得到的轨迹后缀，取精确目标时刻，不按比例生成标签。测试另行克隆单条样本，独立推进各 horizon，与缓存标签逐项比较。

十类场景各25个：正常/强雨/极端雨健康泵、强雨/极端雨退化泵、P03离线、单备用泵、双备用泵、过热、低效率。初始水位0–12cm，雨量幅度和爬升时间、额定能力、初始效率、人员/车辆数量均有变化；退化覆盖立即故障与计划故障。

随机种子42，经 SeedSequence 生成不同场景种子。按场景族分层，再按整个场景划分：170训练、40验证、40测试，分别40800/9600/9600行。一个场景不会跨集合，测试集不参与参数选择。

完整 `data/training.npz` 加入 `.gitignore`；保留200条 sample.csv、场景种子/分组 metadata、分布报告和模型。规模约2.8MB压缩训练数据、7MB模型包。分布报告含雨量、水位、P03效率和当前风险的分位数与直方图。

## 特征合同

`FEATURE_VERSION = m6-v1`，统一 `build_features()` 输出30项有序 float32 特征：

- 当前雨量、瞬时计划变化速度、目标雨量、未来10/20/30分钟的计划平均雨量。
- 当前水位、积水面积、体积、60秒窗口上涨速度、自然排水能力。
- 运行泵额定能力与有效能力；P01/P02/P03 的指令、效率、额定排量。
- P03故障类型、故障年龄、尚未触发的计划故障剩余时间。
- 人员/车辆数量、当前规则风险、阶段、场景持续时间。

未来计划雨量是预测发出时已知的输入假设，不是未来观测值。故障年龄上限1800秒，计划故障不存在时使用-1。状态/阶段/故障编码集中在 config.py，禁止 UUID、时间字符串、名称等无意义输入。

HI和Isolation Forest分数继续由M3提供，但不作为本版水位/规则风险标签的独立决定因子：它们是设备工况的派生诊断，M5排量由实时效率与泵指令决定，避免训练/推理时另造一套诊断值。

## 训练与评估

六个独立回归器：water_10m/20m/30m、risk_10m/20m/30m。使用 CPU histogram、squarederror、学习率0.05、最多600棵树、subsample/colsample 0.85、L2=2、4线程、random_state=42，验证早停35轮。

比较深度4/6/8三组配置，以两个30分钟目标的验证RMSE除以各目标训练标准差后取均值选择配置。实际选择深度4。保存最佳迭代截断后的原生 JSON，使离线评估、在线预测和SHAP使用同一组树。

`evaluate.py` 独立加载保存的六个模型，在验证集和未参与选择的测试集上实际计算 MAE/RMSE/R²，风险另报告分级一致率。评估与在线均执行水位非负、风险0–100裁剪。

metadata.json 包含版本、特征版本/名称、生成器版本、时间、样本量、场景数量、种子、参数、迭代数、实际指标、输入范围、全局增益和各模型SHA256。后端遇到特征版本/名称、维度或校验和不匹配时拒绝ML，保留物理预测；启动仅加载，不训练。

## 解释

全局 `gain` importance 保存于 reports/feature_importance.json，表示总体模型，不冒充当前解释。

当前解释调用 XGBoost 原生 `pred_contribs=True` 的 TreeSHAP，默认仅解释 +30分钟风险。每项显示有符号分数贡献和绝对贡献占比；bias + 全部贡献 ≈ 原始预测（裁剪前）。前八项以外保留 otherContribution，接口支持10/20/30分钟。

不依赖独立 `shap` 包。原生解释不可用时降级为全局增益×当前特征标准化绝对偏离度，明确标注近似、无方向、不可加和，不能称为因果关系。实现依据：[XGBoost官方Python API](https://xgboost.readthedocs.io/en/stable/python/python_api.html)。

## 预测与缓存

RiskPredictionService 在事件循环上复制真实状态与模型内部变量，再把只读副本交给工作线程。ML与物理预测共享相同基准，返回生成时间、场景、会话、revision和场景仿真时间。无事故时不制造高风险或未来曲线。

后台每5墙钟秒刷新，接口也复用缓存；5秒内场景/会话、人员车辆、泵指令/故障、效率与雨量/水位分档等签名未明显改变时复用，返回cacheHit。结果深复制后交给调用者，修改响应不会污染缓存。解释按 horizon/signature 至少复用10秒。

前端每5秒获取预测，解释、模型状态、误差每约10秒获取；离开页面取消请求和计时器，断线保留数据并标注，拒绝其他场景/会话的过时响应。现有实时WebSocket仍为一个。

物理/ML水位差取绝对值，风险差同理。一致度取两项更差的等级：水位差<2cm高，2–5中，>5低；风险差<8高，8–15中，>15低。这是模型一致度，不是概率置信度，也不能证明真实预测准确。

## 采样与真实回测

迁移 `b655e1756d27` 继承 `04ac9081f4fe`，新增risk_predictions。每10个墙钟秒保存一组3个horizon，不每秒写入。保存预测基准、模型版本、ML/物理值、差异等级和后续实际值/误差。同场景同基准同horizon唯一，暂停不重复采样。

PredictionEvaluationService 在既有引擎发布真实状态时观察，不调用预测充当actual。在两次真实观测跨过目标时刻时线性插值，保存观测间隔和 actual - predicted；跨度超过60仿真秒标记 unmatched。10×下典型观测间隔约10仿真秒。

当前场景显示最近最多600条已到期预测的水位/风险MAE，包含之后人工操作造成的差异。尚未达到horizon时显示“预测样本积累中”。超过演示结束时刻的预测保持待评估，不补造actual。Reset/新场景和进程重启令未完成预测interrupted；已采样历史保留，不构成M9复盘。

数据库不可用时实时仿真继续；待评估缓存上限4000、待写缓存上限5000，超限旧记录可过期/丢弃，不保证断库全量补写。场景FK确保只关联已存场景。当前场景MAE来自进程内实际匹配记录，重启后不自动恢复事故。

## API

均为 GET，前缀 `/api/v1/risk`。

| 路径 | 内容 |
|---|---|
| `/prediction?horizons=10,20,30` | current、physicalForecast、mlForecast、comparison、modelStatus、基准和缓存信息 |
| `/model/status` | 可用性、版本、样本量、实际测试指标、平均ML推理耗时、存储状态 |
| `/prediction/explanation?minutes=30` | 当前 TreeSHAP 或明确标记的近似解释 |
| `/evaluation` | 当前场景真实到期样本MAE、样本数和待评估数 |
| `/predictions/{scenario_id}` | 最近300条数据库预测/实际/误差记录 |

ML只支持训练过的10/20/30分钟，其他horizon返回422；原M5forecast API仍支持原有horizon规则。模型文件或依赖缺失时返回available=false、空ML和解释降级状态，物理结果仍保留。

## 页面

/risk 为综合风险研判中心：左侧当前规则风险及10分钟趋势，中间复用M1/M5风险场景、物理/ML对照与真实回测，右侧三档未来预测和当前ML解释。底部两个独立单位图表显示过去30仿真分钟观测实线、未来物理虚线及ML点线；模型卡显示真实测试指标与数据来源。Dashboard只增加一条未来30分钟XGBoost风险和入口。

风险模式默认进入，用户仍可手动控制相机。ECharts复用原ChartCanvas实例；M1–M4原“离开至无canvas页”测试改用/review，因为/risk现在是正式三维页面，不再是占位页。
