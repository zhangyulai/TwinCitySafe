# Milestone 9 完成报告

范围：Timeline Replay & Incident Review，同时覆盖暴雨内涝与管网泄漏。本轮实现、真实网络闭环和历史回放验收均已完成。详细设计见 [M9 架构](M9-architecture.md)，实际证据见 [M9 验收记录](M9-verification.md)。

## 1. 已完成内容

在 M5–M8 已有事故、快照、预测、比较和执行记录上，增加统一事故档案、持久化时间轴、数字孪生历史回放、指标复盘、主工单、人工关闭和模板报告。`/review` 已从占位页升级为事件复盘与工单中心。保留原 Flood/Leak 仿真、M4 管网图、M6 模型与 M7 应急引擎。

## 2. Incident 统一模型

`Incident` 通过事故类型、源事件 ID 和场景 ID 关联原始数据，保存位置、关键时间、观测峰值与关闭结果。支持 FLOOD、PIPELINE_LEAK，以及 OPEN、DETECTED、CONFIRMED、RESPONDING、STABILIZING、CLOSED、ABORTED 状态。Reset、进程中断和场景替换使用 ABORTED，不能被当作正常关闭。

## 3. Timeline 架构

`IncidentRuntimeService` 观察原实时状态，以有界队列交给 `IncidentService` 写入历史。统一事件包含源标识、原始 UTC 时间、事故相对仿真秒、种类和 payload；通过事故、事件类型及来源 ID 去重。读取复盘页不会重新插入时间轴，记录按仿真时间、原始时间和 ID 稳定排序，缺少仿真时间的旧记录保持 null。

## 4. Flood 事件聚合

聚合 M5 暴雨场景、风险阶段和观测采样，关联 M6 预测及实际误差、M7 方案比较、选择、执行步骤、泵启动、入口封控和稳定事件。新采样保留当时设备与入口状态；旧采样未保存的字段明确列入缺失项，不用末态反向填充。

## 5. Leak 事件聚合

聚合 M8 泄漏启动、疑似、确认、风险变化、隔离比较、阀门执行与受控阶段。Incident 的源事件 ID 与场景 ID 分别对应原事件和采样/隔离记录。回放定位使用当时保存的疑似排序，注入目标真值不参与历史定位展示。

## 6. Incident Replay Service

只读服务合并 M5/M8 原始快照和 M9 补充动态快照，不调用 Simulator，不推进实时事故。支持 `from_time`、`to_time`、`step_seconds`，最多返回 2000 个真实观测点；下采样保留首尾和重要离散边界，达到限制时返回提示。历史缺口与缺失字段随 metadata 返回，不生成规则网格或“合理”状态补点。

## 7. Replay Store

独立 `useReplayStore` 只缓存当前事件，切换时清理旧档案并取消过时请求。默认暂停在首个可用样本；支持播放、暂停、停止、拖动和 0.5/1/2/5×，末尾自动暂停。单 RAF 管理播放，卸载时取消。连续观测量可以插值，设备状态、阀门、入口和疑似排名采用左侧离散记录；缺口不插值，部分字段只取同事件此前已保存的有效值。

## 8. Three.js Replay Mode

继续复用 `DigitalTwinScene` 和既有管理器，以 `dataMode=replay` 隔离实时输入。水位、面积、热区、设备、管段、阀门、泄漏效果及受影响建筑由历史状态驱动，拖动时间轴不重新创建场景。未知设备或阀门显示灰色，不把未记录状态默认成正常。静态有效面积仅作为独立渲染依据，不混入历史观测指标。手动操作相机后停止自动事件镜头提示。

## 9. Timeline UI

页面包含事故筛选列表、历史模式标识、三维回放、摘要、播放控制、时间轴、趋势与下方复盘信息。支持类型、状态、日期、关键词和分页。显示原始记录时间与事故仿真时刻；检测、风险、处置、关键和稳定节点使用区分颜色。没有选择事件时不创建 Canvas，离开页面释放场景和图表。

## 10. Key Moments

关键节点优先来自持久化 Timeline，峰值风险与峰值水位由实际历史样本补充抽取。提供开始、异常确认、峰值、处置、稳定和结束快捷跳转，也可点击时间轴 Marker。缺少可定位时间的旧事件保留文字记录，不伪造可跳转时刻。

## 11. Replay Charts

Flood 提供雨量、水位、有效排水能力和规则风险四个 Tab；Leak 提供压力、管段流量、异常匹配度和泄漏规则风险四个 Tab。每次只显示一种单位，完整历史曲线带当前时间游标，点击图表可跳转。缺口以阴影和断线提示。有效泵能力源单位为 m³/s，泄漏/管段流量为 m³/h，压力为 MPa。

## 12. Incident Metrics

指标从数据库保存的观测计算，包括峰值风险、水位、面积、雨量、P03 最低效率，以及管网最低压力、最大流量、最高检测分数和最大影响建筑数。不使用前端当前缓存或源事件末态替代历史峰值；缺少数据时返回 null，页面显示“未记录”。

## 13. Response Metrics

响应指标使用原始 UTC 墙钟时间，区别于加速仿真时间。检测、确认、稳定耗时分别从事故开始计算；响应耗时为首次执行减检测时间。总时长截至正式关闭或最后真实采样，不按查询时刻外推；缺少开始或对应节点时间时不计算。页面说明这些口径。

## 14. Prediction Review

仅对当前 Flood 事件中已到期、且实际水位与风险均已保存的 M6 记录计算误差，展示当时预测、后来 actual、误差与本事件 MAE。物理预测和 ML 预测指标分别保留。页面明确“本事件预测误差”，不替代 M6 独立测试集结论；样本不足如实显示，Leak 不调用内涝 ML 模型。

## 15. Flood Review

展示已保存的 Baseline/A/B/C 比较、实际选择与执行，以及首次执行前和后续最新观测中的水位、风险、雨量及有效泵能力。报告同时说明降雨变化与应急排水对结果的影响，不将全部风险下降归因于方案。入口、积水和设备的未恢复状态不能因为业务关闭而消失。

## 16. Leak Review

展示当时的疑似定位、隔离候选、阀门执行、压力/流量、规则风险与服务影响。执行前后缺少可配对观测时不制造效果差值；旧快照未保存逐栋停水或估算泄漏流量时标明缺失。报告明确泄漏受控与供水恢复是不同状态，供水中断及受影响建筑继续保留。

## 17. Work Order

增加主工单和字符串班组字段。首次处置可自动创建主工单，通过事故 ID 与 category 去重；页面也提供必要的人工创建入口。流程为 PENDING → ASSIGNED → IN_PROGRESS → COMPLETED，接单必须填写班组，完成必须填写结果；不允许直接跳过处理过程。已完成或取消为终态，状态变更形成档案记录。

## 18. Incident Close

仅 STABILIZING 事件允许人工确认关闭；活动 Flood 还核对当前稳定阶段与风险阈值，活动 Leak 还核对 CONTAINED。确认文案为：

> 确认关闭该软件仿真事件？关闭后事件将进入历史复盘，不再作为当前活动事故。

关闭先保存最后真实状态，再写入 CLOSED 与唯一关闭事件，冻结引擎并解除活动事故引用。关闭不会执行 Reset：泵、阀门、入口状态、水量/水位和供水影响继续保留，不代表现场恢复。Dashboard/Risk 不再把已关闭事件作为当前活动事故。重复关闭保持幂等；历史、比较、执行、预测和工单不删除。未完成工单会在关闭区提示。

## 19. Review Report

生成并保存 Web Report，包含事件概况、原因线索、处置过程、预测表现、影响、遗留事项和改进建议，以及生成时的指标对象。使用真实历史数据与固定模板，不接入 LLM，不输出无数据支持的工程结论，不生成 PDF。一个事故保留最新报告，页面可以重新生成。

## 20. Backfill Script

新增 `scripts/backfill-incidents.py`，显式从旧 Flood、Leak、Emergency 和预测表创建统一索引及时间轴。确定性业务标识与唯一约束保证重复执行不重复建档。不删除或重写 M5–M8 原始表，也不把旧 Reset/中断记录改成 CLOSED。`--reconcile-derived` 仅显式合并确证重复的M9派生别名，来源记录保存到payload；真实手动重关和再次稳定仍独立保留。

## 26. 性能和资源情况

Replay服务实测Flood 36.254ms/102点，Leak 18.08ms/31点。100次拖动前后及连续播放后geometry/material/texture均为 **74/98/0**。

真实RAF以5×运行 **120.872墙钟秒**，推进 **601.476历史秒**，超过10分钟等价历史。Flood→Leak→Flood沿用同一Three Canvas和单图表；全局单WebSocket；页面卸载后Canvas与RAF清零；1920/1440无页面溢出。软件渲染采样约28 FPS，实际比赛GPU的45FPS目标仍需设备实测。

## 27. Flood 完整演示流程

1. 在应急推演页启动 M7 暴雨后雨势回落工况，确认软件仿真并使用开发加速。
2. 等待异常、高风险与 P03 退化；暂停后比较四分支，查看共同环境假设并人工选择方案 B。
3. 确认仿真执行，恢复时钟，观察备用泵启动及风险变化，直到 STABILIZING 且满足关闭条件。
4. 进入事件复盘中心，选择当前事故，工单接单、开始处理，填写结果后完成。
5. 填写稳定情况和残余影响，人工确认关闭；确认活动事故解除，入口、水量和设备结果没有被当成恢复。
6. 在同一历史档案中播放、拖动或跳到高风险/方案/稳定节点，查看雨、水位、热区与泵状态。
7. 对照当时比较、实际后续观测与已到期预测误差，生成 Web 复盘报告。

## 28. Leak 完整演示流程

1. 在管网页切换泄漏事故模式并启动软件演示，观察压力、流量、多变量检测及疑似排序。
2. 确认后暂停比较，查看隔离范围和停水影响，预览并人工确认关闭候选阀门。
3. 恢复时钟，观察泄漏流量逐渐衰减，达到 CONTAINED/STABILIZING，同时确认停水建筑仍存在。
4. 在复盘中心完成接单、处理和结果记录，填写仍未恢复的供水影响，再人工关闭事故。
5. 在历史回放中依次查看异常、定位、隔离、阀门关闭与受控阶段；历史阀门变化不能改变当前 M4 阀门。
6. 查看处置前后观测及供水中断，生成模板报告。后续若演示恢复供水，应通过原 M4 明确操作，不将关闭档案视作重开阀门。

## 29. 当前边界

- 全部档案来自软件示范场景；历史回放与模板复盘不构成真实城市安全决策或工程因果证明。
- 旧快照只能展示当时确实保存的字段。未知状态、原始开始时间和采样缺口如实保留，不用最终摘要、当前资产状态或重新运行模拟器补齐。
- 连续量插值用于显示过渡，不是新增数据库观测；离散状态及缺口不插值。静态渲染依据与历史指标区分。
- 归档队列有上限，数据库持续不可用可能丢失中间观测；系统记录错误和丢弃量，不保证恢复未保存的历史。
- 正式关闭冻结并保留入口、积水、设备、阀门和供水影响；不执行自动恢复。Reset/重启中断与正常关闭具有不同业务含义。
- 单事件预测误差不等于模型总体指标；泄漏不适用 M6 内涝模型。模板建议只使用“建议评估”等有边界的表达。
- 当前为单 worker 内存引擎、字符串班组和 Web 报告，没有复杂人员权限、真实调度、LLM Agent、移动端或 PDF 导出。
